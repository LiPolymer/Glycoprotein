# Glycoprotein.Tests

xUnit 测试项目，用于验证 Glycoprotein 库。由原 `Glycoprotein.Debug` 控制台程序（自制 scenario runner）重构而来：
每个 scenario 现在是一个 `[Fact]` 异步测试，断言使用 xUnit `Assert`，节点输出使用 `ITestOutputHelper`。

## 运行

```bash
dotnet test Glycoprotein.Tests/Glycoprotein.Tests.csproj
```

想在控制台看到 `ITestOutputHelper` 的步骤日志（`▶`/`✓`）需要加 `verbosity=detailed`：

```bash
dotnet test Glycoprotein.Tests/Glycoprotein.Tests.csproj --logger "console;verbosity=detailed"
```

> 默认控制台 logger 对**通过的**测试不显示输出（防刷屏）；测试**失败**时其日志会自动附在错误信息里，无需参数。
> 在 Rider / VS 的 Test Explorer 中选中测试，Output 面板即可看到日志，同样无需参数。

生成 JUnit XML 报告（CI 中由 GitLab 的 `reports: junit:` 原生渲染）：

```bash
dotnet test Glycoprotein.Tests/Glycoprotein.Tests.csproj --logger "junit;LogFileName=results.xml"
```

> 需要测试项目引用 `JUnitTestLogger` 包（已在 `Glycoprotein.Tests.csproj` 中）；产物默认在 `TestResults/results.xml`。

## 场景

| 测试类 | 覆盖内容 |
| --- | --- |
| `MasteredHubTests` | Unix Domain Socket hub-and-spoke + 主节点选举：RPC、action、事件 |
| `MeshCommunicationTests` | Unix Domain Socket mesh：RPC、action dispatch、事件 pub/sub |
| `HubFailoverTests` | 杀掉 hub 后幸存节点重新选举并继续通信；调用已死节点必须失败 |

## 说明

- 每场景一个 `[Fact]`（内部多步骤内联断言），与旧版"每场景一个 scenario"语义一致。
- 每个步骤经基类 `ScenarioTestBase.StepAsync` 输出 `▶`/`✓`/`✗` 日志（`ITestOutputHelper`），失败步骤先打 `✗` 再抛出，保持 xUnit 失败即失败语义。
- 旧版 `--list / --scenario / --interactive / --output` 等 CLI 选项已被 `dotnet test` 的过滤与输出取代。
